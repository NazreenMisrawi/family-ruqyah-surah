# GROK BUILD — DAILY RUQYAH AND SURAH
## Complete Web Application Specification — Version 1.0

Build a fully functional, mobile-responsive web application called **Daily Ruqyah and Surah**.

The application is intended for family members to access daily Quranic audio and recitations independently on their own devices.

IMPORTANT: Read this entire specification before beginning development.

The uploaded design reference, recitation images and requirements below are the authoritative source for the application.

Do not stop at generating a visual mock-up. Build the actual working web application.

# 3. AUDIO PLAYER

Place the Audio Player inside a large white rounded container directly below the header.

Section heading:

**Audio Player**

Subtitle:

Your daily listening sequence

Inside the container, create a prominent dark forest-green playback panel.

Include:

- NOW PLAYING label.
- Current audio filename/title.
- Short playback description.
- Audio progress bar.
- Elapsed time.
- Total duration.

Below the playback panel, display:

**PLAYBACK ORDER**

Show three compact horizontal rows:

| Track | Description |
|---|---|
| 01 — Audio 1 | Plays first |
| 02 — Audio 2 | Automatically follows Audio 1 |
| 03 — Audio 3 | Repeats until sequence is restarted |

The current track must be visually distinguishable.

## Playback behaviour

Implement the following sequence:

1. Audio 1 plays first.
2. Audio 2 starts automatically when Audio 1 finishes.
3. Audio 3 starts automatically when Audio 2 finishes.
4. Audio 3 loops indefinitely.
5. Audio 3 continues looping until the user restarts the sequence.

Playback should only begin after the user presses Play.

Implement:

- Play/Pause.
- Seek/progress bar.
- Elapsed time.
- Total duration.
- Current track display.
- Restart sequence.

The restart control must return playback to Audio 1.

Ensure only one audio file plays at a time.

Handle audio loading errors and playback interruptions gracefully.

## Future audio integration

Create a central audio configuration module containing:

- Audio 1: `/audio/Ruqyah Ain.mpeg`
- Audio 2: `/audio/Ruqyah Jin.mpeg`
- Audio 3: `/audio/Surah Al-Baqarah.mpeg`

When deployed, these files will reside under `public/audio/`.

Use relative paths that work in the deployed application.

The application must not require changes to the player logic when these files are added.

If audio files are unavailable:
- Show a clear, unobtrusive message that audio is not yet configured.
- Disable playback controls that cannot function.
- Keep the player layout intact.
- Do not display fabricated durations or playback progress.

# 9. COUNTER FUNCTIONALITY

There are six independent counters:

| Recitation | Counter | Target |
|---|---|---:|
| Recitation 1 | Subuh | 3 |
| Recitation 1 | Asar | 3 |
| Recitation 2 | Subuh | 3 |
| Recitation 2 | Asar | 3 |
| Recitation 3 | Daily Count | 100 |

All counters must be functional.

Rules:

- Plus increases the count by one.
- Minus decreases the count by one.
- Minimum value is zero.
- Maximum values are determined by the respective targets.
- Update the display immediately.
- Store values using browser local storage.
- Preserve counts after page refreshes and browser restarts.
- Do not reset counts simply because the page is refreshed.

## Daily reset

Use the device's local calendar date.

When a new local calendar day begins, reset all six counters to zero.

Store the date associated with the counters so that the application can detect whether a new day has started.

If the user leaves the application open across midnight, detect the date change and reset the counters when the application next becomes active.

Do not synchronise counters between devices.
